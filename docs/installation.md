# Повторная установка и восстановление состояния

Запускать из любого каталога:

```sh
/path/to/dotfiles/install_macos
/path/to/dotfiles/install_linux
```

Оба entrypoint используют `scripts/install_all`: сначала git submodules, затем зависимости, terminal, Vim, VS Code и Zed. На macOS зависимости устанавливаются **до** terminal-шагов. Ошибка директивы Dotbot останавливает дальнейшую установку и возвращает ненулевой код.

`--exit-on-failure` действует между директивами YAML. Поэтому три команды установки расширений VS Code оформлены отдельными директивами `shell`: после сбоя одной следующие не запускаются. Внутри одного вызова `install_vscode_extensions` ошибки отдельных расширений по-прежнему собираются, чтобы показать все неустановленные ID; затем скрипт возвращает ошибку.

Внешние `install_linux`/`install_macos` возвращают код Dotbot (1 при ошибке директивы), который может отличаться от кода вложенной команды. Исходный код и причина ошибки выводятся внутренним установочным скриптом в stderr. При прямом запуске Dotbot для остановки после ошибки также нужно передать `--exit-on-failure`.

## Что восстанавливается

| Состояние | Повторный запуск |
|---|---|
| Симлинка нет | Создаёт родительские каталоги и ссылку |
| Ссылка ведёт в старый checkout или несуществующий путь | Заменяет ссылку на актуальную |
| Ссылка уже правильная | Оставляет её на месте, не меняя inode без необходимости |
| На месте ссылки обычный файл или каталог | Возвращает ошибку; содержимое не удаляет. Сначала сохраните файл/каталог и освободите место для ссылки |
| Исходного файла в репозитории нет | Возвращает ошибку, не удаляет существующий пользовательский файл |
| Отсутствует каталог Vim-плагина | `PlugInstall --sync` скачивает его; установщик проверяет Git HEAD всех объявленных плагинов |
| Нет vim-plug или одного из словарей en/ru | Скачивает отсутствующий файл через временный файл |
| Не установлен Ruff/basedpyright | pip устанавливает недостающий пакет в выделенное окружение |
| Не хватает расширения VS Code | Устанавливает только отсутствующие ID отдельно в каждом профиле |
| Пакеты CSpell удалены из node_modules | npm восстанавливает их по существующему manifest/lock; повторный запуск не запрашивает latest для уже объявленных пакетов |
| Отсутствует checkout Oh My Zsh/pyenv/pyenv-virtualenv/fzf-tab/fzf-simple-git | Клонирует во временный каталог, проверяет обязательный файл и переносит на место |

Существующие Git-checkout shell-инструментов не обновляются через `git pull`; локальные правки сохраняются. Обновление инструментов — отдельное действие. fzf устанавливается системным пакетным менеджером, второй clone в `~/.fzf` больше не создаётся.

fzf-tab и fzf-simple-git хранятся в `~/.local/share/dotfiles/zsh`, вне каталога
конфигурационных симлинков. fd, zoxide и difftastic добавлены в списки системных
пакетов обеих ОС. Клавиши, предпросмотр и проверка: [terminal.md](terminal.md).

Загрузчики fnm и uv запускаются только при отсутствии команды, не переписывают `.zshrc` и не запускают новый shell. Если текущий Node слишком стар для CSpell, Zed-шаг использует Node 24 через fnm, не переключая существующий пользовательский default. При повторном запуске уже установленный Node 24 используется повторно.

Расширения **Zed** восстанавливает сам Zed при запуске, по `auto_install_extensions` из связанного `settings.json`. Shell-установщик подготавливает конфиг и внешние инструменты; он не выдаёт это за проверку загруженных расширений в работающем редакторе. После восстановления конфигурации перезапустите Zed.

## Границы восстановления

Целевое состояние гарантируется успешным завершением соответствующих шагов при доступных пакетных источниках и выполненных системных требованиях. Отсутствие сети, несовместимая версия Vim, отсутствующий CLI VS Code, конфликт обычного файла со ссылкой или повреждённый непустой checkout дают явную ошибку. Для VS Code на macOS предусмотрен поиск CLI внутри установленного приложения; также можно задать `CODE_BIN`.

Произвольные повреждения содержимого существующих Git-репозиториев не исправляются через `reset --hard`: это могло бы уничтожить локальные изменения. Неполный непустой checkout shell-инструмента требует ручного разбора. Для повторной загрузки Vim-плагина с повреждённым checkout сохраните его каталог вне `plugged`, затем повторите установку.

На macOS зависимости по-прежнему устанавливают только `brew`/`tap` из Brewfile, а десктопные приложения (`cask`) подключаются отдельно. Zed и iTerm2 исправлены на `cask`, чтобы Homebrew не пытался устанавливать несуществующие formula. VS Code должен быть установлен до этапа его расширений; отсутствие редактора теперь является явной ошибкой.

Не выполняются `PlugClean!`, удаление лишних расширений, очистка чужих broken symlinks в домашнем каталоге и массовое удаление пакетов. `force: true` для VS Code-ссылок убран: обычные файлы не стираются. Дополнительные пользовательские расширения остаются установленными.

Если пакетный менеджер предлагает обновить зависимости или поставить недостающие пакеты, это может менять системное окружение. Повторная установка не означает побайтовую неизменность всей ОС; её задача — восстановить объявленные ссылки и необходимые инструменты.

## Ограничить запуск только ссылками

```sh
./install_macos --only link
./install_linux --only link
```

Этот режим пропускает команды установки пакетов и инструментов, но инициализация submodules остаётся необходимой для Dotbot. Аргументы передаются как отдельные аргументы, включая пути с пробелами. Успешный запуск с `--only link` проверяет только ссылки, а не полноту установки плагинов.

## Проверки

```sh
python3 tests/test_navigation.py
shellcheck -x scripts/install_terminal home/.local/bin/dotfiles_previewer
```

Тесты используют временные каталоги и локальный Git-репозиторий, не меняют HOME
и не устанавливают пакеты. Проверяются повторная установка checkout, сохранение
локальных правок, восстановление удалённого checkout, предпросмотр и функции
копирования путей Vim. Эти проверки не заменяют полный прогон установщиков ОС.

Для новых terminal-настроек отдельно проверены загрузка настоящих fzf-tab и
fzf-simple-git, повторное подключение конфигурации и выбор Git-объектов.
Dotbot проверен на временном пути: создание, повторный запуск, исправление
неверной ссылки и восстановление удалённой ссылки. Системные зависимости
Homebrew/apt и сочетания клавиш в GUI в рамках этих проверок не устанавливались
и не запускались. Подробнее: [terminal.md](terminal.md).
