# Сочетания клавиш: VS Code, Zed и Vim

Справочник по настройкам этого репозитория. Сначала приведены общие сочетания,
затем различия и команды отдельных редакторов. Описаны явные привязки из конфигов
и несколько стандартных клавиш, необходимых для сравнения. Полные стандартные
раскладки редакторов и всех плагинов сюда не входят.

## Как читать обозначения

- `,w` — последовательно нажать запятую и `w`. Лидер в VSCodeVim и Vim — `,`;
  в Zed последовательности с запятой прописаны непосредственно.
- `Ctrl+K → S` — нажать `Ctrl+K`, отпустить, затем нажать `S` без Shift.
- `H`, `L`, `N`, `S`, `K` — заглавные буквы, то есть с Shift.
- `Normal` — обычный режим Vim; `Visual` — выделение; `Insert` — ввод текста.
- `Ctrl` остаётся Control и на macOS. `Cmd` — отдельная клавиша Command.
- «Нет явной привязки» означает отсутствие настройки в репозитории, а не отсутствие
  такой возможности в редакторе. Стандартные сочетания могут сохраняться.

В таблицах Vim-команд подразумевается **Normal**, если режим не указан отдельно.
В Zed пользовательские Vim-привязки работают в редакторе при закрытом меню (`!menu`).
В VS Code нужен включённый VSCodeVim; в Zed включён `vim_mode`.

## Общие сочетания для трёх редакторов

Клавиши совпадают, но некоторые команды открывают разные представления или имеют
разную область действия. Зависимости Vim перечислены ниже.

| Клавиши | VS Code | Zed | Vim |
|---|---|---|---|
| `H` / `L` | Предыдущий / следующий буфер через VSCodeVim | Предыдущий / следующий элемент текущей панели | Предыдущий / следующий буфер |
| `j` / `k` | Вниз / вверх по отображаемым строкам, Normal и Visual | То же | То же |
| `n` / `N` | Следующее / предыдущее совпадение поиска, затем центрирование | То же | То же |
| `,w` | Сохранить все изменённые файлы | Сохранить все изменённые файлы | Сохранить все изменённые буферы (`:wall`) |
| `,e` | Открыть проводник | Переключить фокус проводника; также в Visual | Открыть / сфокусировать NERDTree |
| `,ts` | Показать / скрыть основную боковую панель | Показать / скрыть правую панель | Показать / скрыть NERDTree |
| `F1` | Показать / скрыть основную боковую панель; глобальная привязка | Показать / скрыть правую панель; глобальная привязка | Показать / скрыть NERDTree в Normal |
| `,to`, `,b` | Выбрать открытый редактор во всех группах | Открыть переключатель вкладок текущей панели | Выбрать открытый буфер через fzf `:Buffers` |
| `,f` | Найти файл по имени через Quick Open | Найти файл через File Finder | Найти файл через fzf `:Files` |
| `,tgv`, `,gs` | Открыть SCM; `,tgv` дополнительно фокусирует следующую группу ресурсов | Переключить фокус Git-панели | Открыть Git status через Fugitive (`:Git`) |
| `,gf` | Буквальный поиск слова / выделения по рабочему пространству | Буквальный поиск слова / выделения по проекту | Буквальный поиск слова / выделения через rg и fzf |
| `,s` | Открыть поиск по содержимому с пустым запросом | Открыть поиск по проекту и очистить запрос | Открыть `:Rg` для ввода запроса в текущем рабочем каталоге |
| `,gd` | Перейти к определению | Перейти к определению | Перейти к определению через ALE; локально для Python |
| `K` | Документация / тип символа | Документация / тип символа | `ALEHover` для Python; для остальных языков стандартный Vim K |
| `,gr` | Найти ссылки и открыть дерево References | Найти все ссылки | Найти ссылки через ALE; локально для Python |
| `,gu` | Открыть ссылки через `editor.action.goToReferences` | То же действие, что `,gr` | То же действие, что `,gr`; локально для Python |
| `,df` | Форматировать текущий документ **без сохранения** | Исправить / отформатировать **без сохранения** | Исправить / отформатировать буфер через ALE **без сохранения** |
| `[d` / `]d` | Предыдущая / следующая диагностика текущего файла (`prev` / `next`) | Предыдущая / следующая диагностика редактора | Предыдущая / следующая диагностика ALE в текущем буфере, с переходом через конец списка |
| `[c` / `]c` | Предыдущее / следующее изменение; вызываются команды обычного и diff-редактора | Предыдущий / следующий Git-hunk | Переходы GitGutter; в diff-mode — стандартные переходы Vim |
| `s`, затем два символа | EasyMotion (`leader leader 2 s`) | Sneak вперёд; также в Visual | EasyMotion вперёд по двум символам, включая другие окна |

Для `n` направление задаётся последним поиском `/` или `?`; `N` идёт в обратную
сторону. Для переходов по визуальным строкам нужен перенос текста: в обычном Vim
по умолчанию задан `nowrap`, но TeX-ftplugin включает `wrap`.

### Поиск: ,gf и ,s

`,gf` назначено и в Normal, и в Visual во всех трёх редакторах.
В VS Code и Zed привязка отключает регулярные выражения; используется слово
под курсором или выделение. В VS Code больше нет дополнительного расширения
выделения через `addSelectionToNextFindMatch`. Область поиска и фильтры задаются
рабочим пространством и настройками панели поиска.

В Vim `,gf` использует `rg --fixed-strings`: спецсимволы ищутся буквально.
Поиск начинается от корня Git-репозитория текущего файла; если определить его
нельзя, используется текущий рабочий каталог (`:pwd`). В Visual поддерживается
только посимвольное выделение в одной строке; многострочное, построчное и блочное
выделения отклоняются с сообщением. Регистры и буфер обмена при чтении выделения
не меняются.

В Vim `,s` и `,?` вызывают обычный `:Rg`: это ввод поискового выражения относительно
текущего рабочего каталога, без автоматической подстановки слова и выбора Git-корня.
В Zed окружение выделения добавляется через Visual `S`; `,s` задано в Normal.

### Форматирование: ,df и сохранение

| Редактор | Что задано в конфигурации |
|---|---|
| VS Code | `editor.action.formatDocument`: форматтер текущего языка; для Python — Ruff. Автоисправления и сортировка импортов отдельно через Code Actions |
| Zed | `editor::Format`: не сохраняет файл. Для Python заданы Ruff fix-all, сортировка импортов и форматирование Ruff |
| Vim | `ALEFix`: запускает исправления асинхронно. Дождаться завершения, затем сохранить через `,w`. В Python: `ruff`, затем `ruff_format` |

Во всех трёх редакторах сохранение выполняется отдельно через `,w`.
В VS Code `,df` не запускает Python-команды в файлах других языков и не требует
Ruff вне Python. Набор автоисправлений у редакторов остаётся различным.

В Vim сортировка импортов Ruff требует включённых правил `I` в конфигурации проекта;
они не навязываются глобально. Обычное сохранение в Vim не запускает ALEFix.
В Zed для Python установлен `format_on_save: off`, но явное `,df` форматирует.
В VS Code поведение обычного сохранения зависит от языка: например, для TypeScript,
Vue и Markdown в репозитории отдельно включён `formatOnSave`.

## Окна, история переходов и предыдущий файл

| Клавиши / задача | VS Code | Zed | Vim |
|---|---|---|---|
| `Ctrl+O` / `Ctrl+I` | Штатная история переходов VSCodeVim | Штатная история переходов панели в Vim-режиме | Стандартная история переходов Vim |
| `Ctrl+^` / `Ctrl+6` | Штатный переход к предыдущему активному файлу VSCodeVim | Предыдущий активный файл панели (`AlternateFile`) | Alternate buffer; передача `Ctrl+6` зависит от терминала |
| `Tab` в Normal | Пользовательское переключение MRU удалено; штатная обработка VSCodeVim | Пользовательское переключение файла удалено; штатная обработка Vim-режима | Не переназначен; в терминале обычно совпадает с `Ctrl+I` |
| `gj` / `gk` | Отдельно не переопределены | Отдельно не переопределены | Физическая строка в Normal и Visual |

`gj/gk` оставлены без изменений и не унифицированы.
Пользовательские переключения окон по `Ctrl+H/J/K/L` удалены.
В Vim остаются стандартные `Ctrl+W`, затем `h/j/k/l`; Insert и сниппеты не изменены.
В Insert у Vim `Ctrl+J/K/L` заняты UltiSnips, см. отдельную таблицу ниже.

## Общие команды интерфейса VS Code и Zed

Это последовательности клавиш интерфейса, а не Vim-leader-команды.
В Vim прямых привязок к ним нет; в последнем столбце указан ближайший настроенный аналог.

| Клавиши | VS Code | Zed | Аналог в Vim |
|---|---|---|---|
| `Ctrl+K → S` | Сохранить всё | Сохранить всё | `,w` |
| `Ctrl+K → T` | Открыть проводник | Переключить фокус проводника | `,e` |
| `Ctrl+K → G` | Открыть SCM при доступном провайдере (`workbench.scm.active`) | Переключить фокус Git-панели | `,tgv` / `,gs` |
| `Ctrl+K → F` | Открыть поиск по файлам | Открыть поиск по проекту | `,s` для ввода запроса, `,gf` для слова |
| `Ctrl+K → R` | Открыть поиск и замену по файлам | Открыть поиск с включённой заменой | Явного аналога поиска и замены по проекту нет |

Боковая панель VS Code настроена справа; в Zed проводник и Git-панель также справа.
Но `,ts`/`F1` в Vim управляют только деревом NERDTree, а не всеми боковыми окнами.

### Встроенный терминал

| Клавиши | VS Code | Zed |
|---|---|---|
| `Ctrl+B → N` | Следующий терминал | Следующий элемент панели с терминалом |
| `Ctrl+B → P` | Предыдущий терминал | Предыдущий элемент панели с терминалом |
| `Ctrl+B → X` | Завершить активный терминал | Закрыть активный элемент панели |
| `Shift+Enter` | Отправить Escape и возврат каретки (`\u001b\r`) | Отправить ту же последовательность |

В Zed эти четыре привязки ограничены контекстом `Terminal`.
В VS Code все четыре привязки ограничены `terminalFocus`; в редакторе
`Ctrl+B` больше не перехватывается терминальными последовательностями.
В Vim такие последовательности не назначены; терминальные и tmux-префиксы
остаются в ведении терминала и tmux.

## Выделение, копирование и окружение текста

| Действие / режим | VS Code | Zed | Vim |
|---|---|---|---|
| Копировать в Visual | Обычный `y`, отдельного переназначения нет | Обычный `y`, отдельного переназначения нет | Обычный `y`, отдельного переназначения нет |
| Системный буфер обмена | `vim.useSystemClipboard: true` | `vim.use_system_clipboard: always` | `clipboard=unnamedplus,unnamed`, только если сборка имеет `+clipboard` |
| Добавить окружение выделению | `S`, затем символ окружения; встроенный surround VSCodeVim включён явно | `S`, затем символ окружения | `S` через vim-surround, затем символ окружения |
| Прыжок по двум символам назад | Отдельного `S` в конфиге нет | `S` — Sneak назад только в Normal | Отдельного `S` в Normal нет; в Visual `S` занят vim-surround |
| Комментарий | В репозитории отдельной команды комментирования не назначено | Отдельной команды комментирования не назначено | `Ctrl+_` через NERDCommenter, Normal и Visual |

В Zed Visual `S` добавляет окружение, а `y` копирует сразу: многоклавишных
пользовательских привязок с префиксом `y` нет. В терминальном Vim доступность системного буфера зависит
также от окружения. `Ctrl+/` часто передаётся терминалом как `Ctrl+_`, но это зависит
от терминала: в конфиге Vim назначен именно `Ctrl+_`.

## Дополнительные команды VS Code

Все сочетания ниже работают в Normal через VSCodeVim.

| Клавиши | Действие и отличия |
|---|---|
| `,z` | Закрыть нижнюю и боковую панели, свернуть дерево проводника, минимизировать остальные редакторы, закрыть редакторы других групп и все diff-редакторы Git. Это несколько действий, а не просто переключение Zen Mode |
| `,gh` | Переключить исходник / заголовочный файл через `C_Cpp.SwitchHeaderSource`. Требует расширения C/C++; его нет в текущих списках default/python |
| `,tgg` | Переключить нижнюю панель, открыть SCM, закрыть все группы редакторов, открыть Git Graph и разделить редактор вниз. Команда меняет расположение редакторов |
| `Space` | Сфокусировать breadcrumbs и открыть выбор элемента |
| `,tr` | Сфокусировать дерево References. В Vim эта последовательность заново ищет ссылки через ALE; в Zed отдельно не назначена |

### Отключённые привязки VS Code

Записи с `-` перед `command` снимают конкретную стандартную привязку. Они не означают
полного запрета клавиши во всех контекстах и сами по себе не назначают новую команду.

| Клавиши | Что отключено или заменено |
|---|---|
| `Ctrl+K → S` | Save Without Formatting заменено на Save All |
| `F1` | Палитра команд заменена переключением боковой панели |
| `Ctrl+Shift+E` | Открытие проводника; также выделение до конца строки в поле ввода |
| `Ctrl+B` | Переключение боковой панели; сочетание используется как префикс терминальных команд |
| `Ctrl+Shift+G` | Стандартное открытие SCM при активном провайдере |
| `Cmd+Shift+F` / `Cmd+Shift+H` | Стандартные поиск / замена по файлам на macOS |
| `Ctrl+P` | Перехват расширением Vim в редакторе и командной/поисковой строке Vim |
| `Ctrl+Left` | Перехват расширением Vim вне Insert |
| `Ctrl+/` | Четыре контекстные команды: принятие подсказки в accessibility view, запуск из чата в терминале, режим пояснений подсказок, отправка последовательности в терминал |
| `Ctrl+I` | Две команды голосового чата: запуск ввода и остановка с отправкой |
| `Ctrl+Cmd+Right` | Перенос редактора в следующую группу, фоновое подтверждение quick pick и изменение размера терминала вправо |
| `Ctrl+Cmd+Left` | Перенос редактора в предыдущую группу и изменение размера терминала влево |
| `Ctrl+Q` | Закрытие VS Code |
| `Cmd+K → F` | Закрытие папки / рабочего пространства |

`vim.handleKeys["<C-k>"] = false` передаёт `Ctrl+K` самому VS Code.
Существующие последовательности `Ctrl+K → …` сохранены; одиночный `Ctrl+K`
не назначен на переключение окна.
Отключения с `Cmd` относятся к macOS; автоматической замены на `Ctrl` конфиг не задаёт.

| Клавиши | Режим | Действие / зависимость |
|---|---|---|
| `,nt` | Normal | Переключить NERDTree; аналог `,ts` |
| `,b` | Normal | Выбрать буфер через fzf; аналог `,to` |
| `,f` | Normal | Найти файл через fzf `:Files` |

| `,?` | Normal | Ввести запрос `:Rg`; аналог `,s` |
| `,gs` | Normal | Git status через Fugitive; аналог `,tgv` |

| `,dc` | Normal | Повторно запустить диагностику ALE |

| `Ctrl+K` | Insert / работа со сниппетом | Предыдущее поле UltiSnips |
| `Ctrl+L` | Insert / работа со сниппетом | Список подходящих сниппетов UltiSnips |

LSP-привязки `K`, `,gd`, `,gr`, `,gu`, `,tr` создаёт Python-ftplugin при наличии ALE;
при смене типа файла они удаляются. Они не подключены ко всем языкам автоматически.
Markdown-ftplugin настраивает текст и орфографию, но собственных клавиш не добавляет.

Клавиши NERDTree, Tagbar, Undotree, fzf, Fugitive, EasyMotion, NERDCommenter и ALE
подключаются только при наличии соответствующего плагина. `[c`/`]c` предоставляет
GitGutter, а Visual `S` — vim-surround. Для поиска по содержимому нужен `rg`,
для меню fzf — бинарник `fzf`; UltiSnips требует Vim с `+python3`.
Подробнее об установке и настройке языков: [vim.md](vim.md).

[python/extensions.txt](../home/.code_profiles/python/extensions.txt) добавляет
Python-расширения, но не отдельный набор клавиш. Настройки конкретного рабочего
пространства, пользовательские изменения и `~/.vim/local.vim` могут менять поведение.

Проверить фактическую привязку Vim можно через `:verbose nmap ,gd`,
`:verbose xmap ,gf` или `:verbose imap <C-j>`. В VS Code используйте редактор
Keyboard Shortcuts для команд интерфейса и разделы `vim.*` для переназначений Vim;
в Zed сверяйте активный контекст с `keymap.json`.
