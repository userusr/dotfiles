# Vim в dotfiles

Конфигурация рассчитана на Vim 9.1+ в macOS и Linux. Плагины управляются vim-plug. Python использует ALE, Ruff и basedpyright; сниппеты — UltiSnips. Открытие Vim не устанавливает пакеты и не обращается к сети за плагинами.

## Установка

Команды выполняются из корня репозитория. Сначала нужны системные программы: Vim с `+python3`, `+job`, `+channel`, `+keymap`, git, curl, Python 3 с venv, ripgrep, fzf, Universal Ctags, ShellCheck и yamllint.

macOS:

```sh
# Только если установлен старый formula ctags:
brew unlink ctags
brew install vim git curl ripgrep fzf universal-ctags shellcheck yamllint
./dotbot/bin/dotbot -d . -c macos/steps/vim.yml
```

Debian/Ubuntu с доступным Vim 9.1+:

```sh
sudo apt update
sudo apt install vim-gtk3 git curl python3 python3-venv ripgrep fzf universal-ctags shellcheck yamllint
./dotbot/bin/dotbot -d . -c linux/steps/vim.yml
```

В старом дистрибутиве сначала обновите Vim до поддерживаемой версии. Для сервера можно выбрать `vim-nox`, но его поддержка clipboard отличается. На X11/Wayland проверяйте реальное копирование в другое приложение; наличие `xclip` или `wl-copy` само по себе не подключает clipboard к Vim. Без графической сессии доступны внутренние регистры.

Шаги создают симлинки отдельных конфигурационных файлов, скачивают vim-plug и плагины, устанавливают Ruff/basedpyright в `~/.local/share/vim-tools`, а словари en/ru — в `~/.vim/spell`. Обычные файлы на месте будущих симлинков не перезаписываются: сначала сохраните и перенесите их вручную. Весь `~/.vim` не является симлинком и не хранится в git.

После создания симлинков установку можно повторить:

```sh
bash scripts/install_vim
```

Повторный запуск не обновляет уже установленные Python-пакеты через `--upgrade`, не удаляет плагины, не перезаписывает `local.vim` и пользовательские словари. Поддерживаются `VIM_BIN`, `VIM_USER_DIR`, `VIM_TOOLS_DIR` для отдельной установки; в выбранном runtime заранее должны быть конфигурационные симлинки. По умолчанию на macOS установщик выбирает Homebrew-Vim, даже если текущий PATH ведёт к системному.

После изменения `.zshrc` откройте новый терминал. Проверьте:

```sh
command -v vim
vim --version
ctags --version
```

Ctags должен сообщать `Universal Ctags`. Если старые ссылки мешают установке, отключите только их; пакет удалять необязательно. На Linux проверьте выбор `ctags` в alternatives.

## Файлы и локальные настройки

- `home/.vimrc` — общие настройки, список плагинов и клавиши.
- `home/.vim/after/ftplugin/` — локальные настройки Python, Markdown, TeX и Perl.
- `home/.vim/autoload/dotfiles.vim` — поиск и вспомогательные функции.
- `~/.vim/local.vim` — локальные переключатели перед подключением плагинов; установщик его не создаёт и не перезаписывает.
- `~/.vim/state/{undo,backup,swap}` — локальное состояние с правами 0700.

Пример `~/.vim/local.vim`:

```vim
let g:dotfiles_vim_latex = 1
let g:dotfiles_vim_perl = 1
let g:dotfiles_vim_puppet = 1
" Включить только если в терминале выбран шрифт с Powerline-глифами.
let g:airline_powerline_fonts = 1
```

После включения дополнительных плагинов выполните `bash scripts/install_vim` и перезапустите Vim. VimTeX закреплён на `v2.18` для совместимости с Vim 9.1. Более новые версии могут требовать обновления Vim.

Perl-форматирование требует `perltidy` (`brew install perltidy` / `sudo apt install perltidy`). LaTeX требует отдельного TeX-дистрибутива с `latexmk`, `latexindent` и настроенного PDF viewer. Установка базовой конфигурации не скачивает TeX Live и не добавляет эти инструменты автоматически.

## Клавиши

Лидер — запятая. В таблице последовательности вроде `,df` нажимаются по очереди. Клавиши плагинов подключаются при наличии соответствующего установленного плагина.

| Клавиши | Действие |
|---|---|
| `H` / `L` | Предыдущий/следующий буфер вместо стандартного движения к краям экрана |
| `j` / `k` | Визуальная строка с учётом переноса; `gj` / `gk` — физическая строка |
| `n` / `N` | Следующее/предыдущее совпадение с центрированием |
| `Ctrl+W`, затем `h/j/k/l` | Стандартное перемещение между окнами; одиночные `Ctrl+H/J/K/L` не переназначены |
| `Ctrl+O` / `Ctrl+I` | История переходов назад/вперёд; Tab не переназначен |
| `Ctrl+^` | Alternate buffer |
| `,w` | Сохранить все буферы |
| `,e` | Открыть/сфокусировать дерево файлов |
| `,ts`, `F1`, `,nt` | Переключить видимость дерева |
| `,to`, `,b` | Выбрать открытый буфер |
| `,f` | Найти файл |
| `,/` | Найти строку в открытых буферах |
| `,s`, `,?` | Поиск содержимого через `:Rg` в текущем рабочем каталоге |
| `,gf` | Поиск слова или однострочного символьного выделения как буквального текста; от корня Git-проекта либо cwd вне Git |
| `,gd` | Перейти к определению (Python/LSP) |
| `,gr`, `,gu`, `,tr` | Найти ссылки на текущий символ (Python/LSP) |
| `K` | Документация символа (Python/LSP); в других файлах стандартный Vim K |
| `[d` / `]d` | Предыдущая/следующая диагностика ALE в текущем буфере |
| `,dc` | Повторить проверку ALE |
| `,df` | Исправить и отформатировать буфер через ALE |
| `,pt` | Локальный alias форматирования для Python и доступных Perl/TeX-форматтеров |
| `,mt` | `:make test` в Python/Perl; требуется target test проекта |
| `,gs`, `,tgv` | Git status через Fugitive |
| `,gc` | История коммитов |
| `[c` / `]c` | Переход между изменениями GitGutter; в diff-mode — стандартные diff-переходы |
| `,tb` | Структура файла через Tagbar |
| `,ut` | История undo |
| `s` | EasyMotion по двум символам |
| `Ctrl+_` | Комментарий в normal/visual mode (передача Ctrl+/ зависит от терминала) |
| `,is`, `,ie` | Выбрать сниппет / редактировать сниппеты |
| `Ctrl+j/k` в insert mode | Раскрытие/переходы UltiSnips |
| `y` в visual mode | Сразу копировать; нет многоклавишных привязок с префиксом y |
| `S` в visual mode | Surround выделения через vim-surround |

`ALEFix` асинхронный: дождитесь результата `,df`, затем сохраните через `,w`. Обычное сохранение не форматирует Python. В VS Code и Zed `,df` также не сохраняет файл; различия в наборе исправлений описаны в [keybindings.md](keybindings.md). Не добавляйте `:ALEFix | write`: сохранение может произойти раньше завершения форматирования.

Старые `,se`/`,sc` не оставлены aliases, чтобы не задерживать `,s`. `,gf` не меняет регистры и не включает regex. Многострочное и блочное выделение отклоняются с сообщением. `Ctrl+K` и терминальные `Ctrl+B …` из VS Code не перенесены. Пользовательские переключения окон по `Ctrl+H/J/K/L` удалены; штатные оконные команды и префиксы tmux остаются доступными. Полного аналога Git Graph, Peek Definition и breadcrumbs эта конфигурация не предоставляет.

## Python

В `:ALEInfo` адаптер type-checker называется `pyright`, но запускает `basedpyright-langserver`. Второй линтер — Ruff. Общие настройки проверки типов — `standard`; конфигурация проекта имеет приоритет. ALE ищет `.venv` проекта. Ruff из проекта предпочтительнее общего инструмента, если найден механизмом ALE.

Для сортировки импортов при `,df` добавьте в **проектный** `pyproject.toml`:

```toml
[tool.ruff.lint]
extend-select = ["I"]
```

Без этого дополнительные правила сортировки глобально не навязываются. `ruff check --fix` применяет безопасные исправления, затем `ruff format` форматирует результат. Длина строки и исключения берутся из конфигурации проекта. `--unsafe-fixes` не включён. UltiSnips требует именно `+python3` внутри Vim; одного установленного Python CLI недостаточно.

## Обновление и диагностика

В Vim:

```vim
:PlugStatus
:ALEInfo
:verbose nmap ,s
:verbose nmap [d
:messages
```

Для обновления плагинов сначала сохраните `:PlugSnapshot ~/.vim/plugins-snapshot.vim`, затем выполните `:PlugUpdate` и просмотрите `:PlugDiff`. После проверки работы используйте интерактивный `:PlugClean`. Установщик никогда не запускает `PlugClean!` и не удаляет прежние каталоги автоматически. Snapshot может содержать локальные пути: храните его вне репозитория.

Явное обновление CLI:

```sh
~/.local/share/vim-tools/bin/python -m pip install --upgrade ruff basedpyright
```

Если плагины не установлены, Vim открывается с базовыми настройками и fallback-темой. Он сообщает команду установки один раз за сессию. Русская проверка орфографии в Markdown включается только при наличии обоих словарей; первый запуск не инициирует их скачивание.

Общие гарантии повторной установки и восстановления: [installation.md](installation.md).

## Проверки

```sh
python3 tests/test_vim.py
VIM_BIN=/opt/homebrew/bin/vim python3 tests/test_vim.py  # macOS Apple Silicon
bash -n scripts/install_vim install_macos install_linux
```

Проверки используют временный runtime и state, не меняют HOME и не устанавливают плагины. Они проверяют повторный source, persistent undo, смену filetype, удаление локальных клавиш, поиск специальных символов и сохранение регистров. Работа LSP, полноценного UI, clipboard и Linux-пакетов проверяется отдельно на соответствующей машине.
